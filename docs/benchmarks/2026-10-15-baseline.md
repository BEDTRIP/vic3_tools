# Baseline: three reference tasks before the tools (2026-10-15)

The plan measures the tools by tokens and turns on three reference tasks, before and after stages 2–4. This is the
"before": a fresh agent (Claude Sonnet, a subagent with no conversation context) solves each task with what exists
today — grep, reading files, the repos' `CLAUDE.md`. Each task ran twice. The agent was told not to edit anything.

Setup: local session on the PC (game files, the fork and its tools on disk), mod "E&F: Ledgerdemain" (fork repo,
`master` of 2026-10-15), game 1.13.11.

## Tasks and reference answers

**T1 — where is it defined and who uses it.** "Where is the scripted effect `zz_ef_cur_par_update` defined and where
is it called? path:line of the definition and of every call (mentions in comments are not calls)."
Answer: defined `common/scripted_effects/ld_currency_var.txt:126`; called `ld_currency_var.txt:10` and
`common/scripted_effects/ld_money_model.txt:1050`; three more mentions are comments.

**T2 — fix a widget in a panel.** "In the mod's financial centre window the bond market index block is too narrow —
its label wraps. Make the block 130 wide instead of 100, the label and the block with its background. Give the exact
edit, path:line, was → becomes."
Answer: `gui/ld_cb_rate_panel.gui` (17 295 lines), lines 475–476 (label `minimumsize` / `maximumsize`) and 492–493
(the block's), `100` → `130`; the neighbouring `country_indice` block has the same lines and must stay.

**T3 — the cause of an error from `error.log`.** "The run's `error.log` has many `Variable
'central_bank_debt_privat_bank_buyer_list_N' is used but is never set`. Find the cause: where the variables are read
(the call chain up to what starts it) and why nobody writes them."
Answer: the only writers (`add_to_variable_list`) went to `_archive/ef_ai_treasury_bonds/` (its README, line 27);
readers stayed: lists 1–10 in script values `00_financial_scripted_value.txt:4319–4440`, summed into
`gold_loaned_to_central_bank` / `central_bank_interest_refund_per_year`, read by the effect
`central_bank_interest_refund_per_year_in_gold` (`01_financial_scripted_effects.txt:5217`), called from the yearly
pulse `00_on_action_main.txt:626/631`; all 25 lists also by the `…_N_clear` effects (`08_list_effect.txt:1870+`) behind
a scripted GUI whose button is commented out.

## What this says

- A fresh agent starts at roughly 37–38 k tokens before doing anything (system prompt, tool definitions, the repos'
  `CLAUDE.md`). T1 and T2 cost only ~3–6 k on top of that: with the mod in a local repo, grep finds a unique name at
  once. The tools can not save much there.
- T3 is where the work is: ~20–30 k tokens over the base, 14–18 tool calls, following references up a chain of script
  values and effects by hand. An index with `v3 refs` (stage 2) targets exactly this.
- All six answers were right. The "after" measurement should compare tokens and calls, and keep checking correctness.
- These tasks are easy for grep because the names are unique and the files local. Harder cases worth adding to the
  "after" set: a definition that lives in vanilla or another mod of the playset (which file wins, `vfs_order`), a GUI
  type defined through `using` / `blockoverride` templates, and the same tasks from a cloud session through the bridge.
