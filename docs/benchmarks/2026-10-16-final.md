## What this says

- **With the tools used on purpose the six tasks cost half of the grep baseline, and it holds** (103 k → 55.9 k at
  stage 3 → 53.5 k now). The finished toolset changed nothing for these tasks after stage 3: they need `def`, `refs`,
  `loc`, `winner`, `gui resolve`, all there since stages 2–3. T2 used `gui set --dry` lines correctly — the skill's
  wording fixed after stage 3 works.
- **Without being told, the hook gets the easy lookups for free.** T1: one grep, the hook returned `v3 def` + `v3 refs`,
  done at 4.5 k — cheaper than the told arm. T4 the same. Against stage 2's "rule only" (85.6 / 69.3 k) the natural arm
  (88.6 k) is no better in total, though: on the chain tasks the agent goes back to reading files after the first
  answer. T3: 34.8 k and 11 calls against 16.3 k and 6 when told; T2: 18.8 k, reading the `.gui` instead of `gui set
  --dry`.
- **Not a gap to close.** The hook covers a grep by name; past that the agent chooses its own tools. The user's
  priority (16.10) is the right answer, not the token count, and which tools the agent uses for it is the agent's
  call. Pushing agents into the chain commands was considered and dropped; ~14 % saved unprompted (103.3 → 88.6 k) with
  every answer right is the outcome wanted.
- **The natural arm was more right.** Told agents trusted the index and stopped; the natural ones read more and caught
  details (T3 numbering, T6 key). One run per arm — the spread between runs (stage 2: 24 k vs 36 k on the same arm) is
  as large as some differences; read the sums.
- **T6 stays ambiguous as written** (stage 3): the level "1" fits both keys. A later re-run should use a law that gives
  level 2 or more.
- The fixed start grew again (51.9 k → 54.5 k): more skills listed and longer `CLAUDE.md` files. On T1/T4-like
  questions the start is >90 % of the cost.
