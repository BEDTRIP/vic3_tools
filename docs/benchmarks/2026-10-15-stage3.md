## What this says

- **In total nothing changed** (54.8 k → 55.9 k): with one run per task the spread between runs (stage 2: 24 k vs
  36 k for the same arm on T3) is larger than any difference here. Read it as "the same", not as better or worse.
- **T5 used `v3 gui resolve`**: half the tool calls (8 → 4), the full chain in one answer, including what stage 2
  answers missed — vanilla's `type textbox` sets 17 and loses. The tokens did not fall: the agent read around the
  answer anyway.
- **T2 did not use `v3 gui set`** — the task says "give the edit", and the agent read the lines instead (`refs`,
  `outline`, a 45-line read), then guessed two line numbers from a range and got them wrong by one. `gui set --dry`
  prints the exact lines; the skill's row says "change a property", which an agent does not match to "give the edit".
  The skill now says it.
- **T6 is ambiguous as written**: the shown text «… (1 ур.) …» fits both `INSTITUTION_TYPE_NEW_EFFECT` (a fixed 1) and
  `INSTITUTION_NEW_EFFECT` (the current level, 1 here); the reference answer rests on knowing which key the fork had to
  fix. `v3 loc --text` returns both; the tool can not decide. The task needs the level to be other than 1, or the
  context (a law that raises an existing institution).
- **The installed plugin was 0.2.0** — the skill without the `v3 gui` rows; a real session would not have seen them.
  The marketplace version is now 0.3.0 so `/plugin update` picks the new skill up.
