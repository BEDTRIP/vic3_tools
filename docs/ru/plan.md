# План инструментов для модов Victoria 3

План этого репо. Перенесён сюда из `vic3_mods` 15.10.2026.

## Выжимка разговора (облачная сессия 15.10.2026)

Откуда план. Пользователь спросил, какие расширения нужны Claude Code для дизайна UI (мод Vic3 и отдельный сайт на
PHP), потом — что уже сделало сообщество, потом — каких инструментов не хватает для модов.

**Выводы по дизайну UI.** Дизайн у агента плохой не от незнания, а оттого, что он не видит результат и не опирается на
образец. Нужны цикл «правка → скриншот → правка» и образец (дизайн-система, ванильные типы).

- **Сайт на PHP** (другой проект, к этому плану не относится): плагины `frontend-design` (Anthropic), Impeccable
  (`/plugin marketplace add pbakaus/impeccable`, потом `/impeccable init`, проходы `critique` / `polish`),
  Playwright MCP (скриншоты страниц); готовая CSS-основа (Tailwind / Pico) и раздел про дизайн в `CLAUDE.md` сайта
  со скриншотами-образцами. Taste Skill и UI/UX Pro Max во многом повторяют Impeccable — все сразу не ставить.
- **GUI Vic3:** готовых навыков, предпросмотра и проверок `.gui` в сообществе нет. Есть общий навык
  `victoria3-mod-dev` (trotsky1997) — про события и локализацию, не про GUI. Позже выяснилось: `vic3-tiger` (amtep)
  проверяет и `.gui` — см. «Что уже есть у сообщества».

**Impeccable для Vic3.** Переносится метод, а не содержание: `init` (файл стиля), отдельные проходы с чек-листами,
список антипаттернов, автоматические проверки без модели. Знания там про CSS/DOM, движок проверок на Rust под HTML.
Вывод — свой навык `vic3-gui` в том же духе (этап 7) и проверки GUI в `v3 lint` (этап 4).

**CWTools.** Правила для Vic3 живые (`cwtools-vic3-config`, обновлены в июне 2026 до 1.13.9), но в `config/gui/`
только `text_formats.cwt` и `text_icons.cwt` — виджеты не описаны. Расширение VS Code — для человека; агенту оно
полезно, если подключить сервер языка CWTools к Claude Code через плагин (`.lsp.json`): ошибки после каждой правки,
переход к определению. Мешают не облако, а файлы ванили (нужны на месте) и запуск сервера вне VS Code — не проверено
(этап 5). Предпросмотр GUI внутри CWTools — не там: свой рендер `.gui` → PNG отдельной программой (этап 9).

**Расширения VS Code и плагины Claude Code.** Расширение — для человека в редакторе (подсветка, подчёркивание).
Плагин — для агента: навыки, команды, хуки, MCP-серверы, серверы языка. Один сервер (как у CWTools) может иметь обе
«морды».

**Мост `vic3-pc`** — хорош для прогонов, не для цикла вёрстки. Промежуточный шаг — «стенд»: игра в отладочном режиме,
перечитывание `.gui` на лету (проверить), снимок области (этап 6).

   случай проекта, не ядро.
6. Окружение собирает один раз на машину программа `v3 setup`, обновление — само.

7. Сначала брать готовое у сообщества (tiger, выгрузки Modding-Digests, крючки CMF), своё — поверх.

## Зачем

Агент (облачный и локальный) и человек тратят время и токены на одно и то же: найти определение, прочитать огромный
файл ради одного блока, узнать об ошибке только из `error.log` после прогона, сверстать GUI вслепую. Инструменты
должны:

1. **Отвечать коротко** — `путь:строка` и выжимка, а не файл целиком. Вывод по умолчанию рассчитан на агента
   (ограничен по объёму), `--json` — для других инструментов.
2. **Ловить ошибки до прогона** — проверки скрипта, локализации и GUI, автоматически после правки (хук).
3. **Показывать GUI без прогона** — сначала стенд на живой игре через мост, потом свой рендер `.gui` → PNG.
4. **Быть общими** — работать с любым модом и плейсетом; проектное (компачи, модель денег форка) — снаружи, поверх
   общего ядра.

Мерило: токены и ходы на шесть эталонных задач T1–T6 (найти, где определено и кем используется; поправить виджет в
панели; найти причину ошибки из `error.log`; какой из нескольких GUI-типов побеждает; значение свойства виджета после
шаблонов; какой текст видит игрок) — замер до и после этапов 2–4; замер «до» —
[benchmarks/2026-10-15-baseline.md](../benchmarks/2026-10-15-baseline.md).

Что мешает сейчас:

- **Пути зашиты в код** (`FORK = ../..`, `GAME = C:\games\…`), разные в каждом скрипте.
- **Разовое вперемешку с постоянным:** пробы этапов (`ld_probe_*`, `ld_r1a_checks.py`) рядом с ядром; `_to_delete/`.
- **История в docstring'ах** — номера этапов и даты вместо описания.
- **Нет тестов.**
- **Нет ничего для GUI**, кроме `compare_gui_names.py` и `ld_vitrine.py`. **Нет справочника ванили** — агент ищет в

## Устройство нового репо

```
vic3tools/              пакет Python
  core/                 лексер и парсер с позициями; порядок загрузки (VFS); конфиг путей
  index/                индекс SQLite: определения, ссылки, локализация, GUI-типы и шаблоны, текстуры, defines
  lint/                 правила проверок и один запускатель
  gui/                  оглавление, раскрытие шаблонов, справочник ванили, правка по пути, позже рендер
  compat/               конфликты, матрица пар, кто выигрывает ключ, merge
  save/                 разбор текстового сейва, кеш, запросы
  logs/                 error.log по семействам, сравнение прогонов, места ошибок в коде
  gen/                  каркас генераторов: emit, --check
bridge/                 MCP-сервер ПК (обобщённый мост) и скрипты игры (PowerShell)
claude-plugin/          плагин Claude Code: навыки, хуки, MCP (мост), LSP (CWTools, если подойдёт)
tests/                  тесты на маленьких примерах
```

- **Одна команда** `v3 <подкоманда>` (`v3 def`, `v3 refs`, `v3 outline`, `v3 lint`, `v3 winner`…), у каждой
  `--help`, короткий вывод и `--json`.
- **Проекты подключают пакет** (`pip install -e ../vic3-tools`) и держат своё: генераторы компачей — в `vic3_mods`,
  разборы `eflog` и проверки документов — у форка.

## Откуда берутся файлы

Репо **открытый** (решение пользователя 15.10). В нём — код, правила, документы; **ничего из игры**: ни копий
ванильных файлов, ни текстур, ни выгрузок локализации. Всё, что нужно из игры, инструменты читают на месте, у
каждого пользователя из его папок; индекс, справочник и глоссарий строятся там же, в кеш вне репо.

Три корня — всё, что нужно для работы:

| корень | что там | как найти |
| --- | --- | --- |
| **игра** | ваниль: `game/` (скрипт, GUI, локализация, текстуры), `victoria3.exe` | Steam: `libraryfolders.vdf` → библиотека с приложением 529340 |
| **моды мастерской** | `steamapps/workshop/content/529340/<id>/` — моды как есть, читаются прямо оттуда | та же библиотека Steam |
| **документы игры** | `Documents/Paradox Interactive/Victoria 3/`: `logs/`, `save games/`, `mod/` (локальные моды), `launcher-v2.sqlite` (плейсеты и порядок модов), `content_load.json`, крэш-дампы | папка «Документы» Windows (с учётом переноса в OneDrive) |

- **Определяются сами**, конфиг `vic3tools.toml` — только чтобы поправить найденное. `v3 where` печатает, что
  найдено.
- **Плейсет — из лаунчера:** набор и порядок модов читаются из `launcher-v2.sqlite` (как сейчас
  `playset_content_load.py`); моды берутся из мастерской или из `mod/` по их путям. Своих копий модов не нужно.
- **Дополнительные источники — по желанию проекта:** рабочая копия мода в git (форк), снимки модов по коммитам
  (`vic3_mods_out`, для диффов между версиями) — в конфиге проекта, а не в ядре.
- **Только чтение.** Пишут инструменты в кеш, в папку проекта и, явной командой, в `mod/` (синхронизация живой копии).
- **Облако:** папок игры там нет и копировать их не нужно — облачный агент вызывает те же команды `v3` на ПК через
  мост и получает короткий ответ. Поэтому мост v2 (этап 6) — это «`v3` на ПК», а не набор отдельных инструментов. Что
  не требует игры (разбор файлов проекта, генераторы, проверка документов) — работает в облаке само.
- **Перед публикацией** — проверка на секреты и личное: токен и адрес моста, пути с именем пользователя, почта.

## Установка и обновление

Окружение собирается **один раз на машину** командой `v3 setup`, дальше поддерживается само. Это обычная программа,
а не работа агента: шаги одинаковые и проверяемые. Агент (навык `vic3-setup`) только запускает её, читает отчёт и
помогает там, где нужен человек.

**`v3 setup` на ПК:**

1. Проверить Python, поставить пакет.
2. Найти три корня, показать найденное, записать `vic3tools.toml` (спросить, только если не нашлось или нашлось
   несколько).
3. Построить кеш: индекс ванили и модов плейсета, справочник GUI, глоссарий из локализации.
4. Выгрузки документации игры (`script_docs`, типы данных) — взять из Modding-Digests для своей версии игры; если
   версии там ещё нет — запустить игру один раз с консольными командами и забрать логи (занимает экран —
   предупредить). Поставить tiger нужной версии.
5. Поставить плагин Claude Code: навыки, хуки, MCP моста, LSP (если CWTools подойдёт).
6. По желанию — мост: токен, туннель, автозапуск.
7. В конце — `v3 doctor`: что готово, что нет и почему.

**Обновление — без повторной установки:** кеш помнит версию игры и даты файлов. Вышел патч, обновился мод в
мастерской, сменился плейсет — при следующем вызове переиндексируется только изменённое, а выгрузки из игры (п. 4)
команда сама попросит повторить после смены версии игры.

**В облаке** установки игры нет: хук начала сессии ставит пакет и проверяет связь с мостом. Всё, что требует файлов
игры, идёт на ПК через мост.

## Язык

Репо — для любых мододелов, поэтому основной язык английский, русский — слой локализации (решение пользователя
15.10).

- **По-английски — всё основное:** код, имена, комментарии, docstring'и, `--help`, навыки (`SKILL.md`), документы,
  сообщения коммитов.
- **Русский — локализация, а не второй оригинал:**
  - документы для людей — зеркало `docs/ru/` с теми же разделами; у каждого перевода в шапке отметка, с какой версии
    английского он сделан, и проверка `v3 docs check-ru` показывает устаревшие;
  - вывод команд — каталог сообщений (`en` по умолчанию, `ru`), язык — из конфига или окружения;
  - навыки остаются английскими (агенту так надёжнее), но велят **отвечать на языке пользователя**.
- **Термины без додумывания:** глоссарий en ↔ ru, собранный из локализации самой игры (английский и русский текст по
  одному ключу), — агент называет вещи так, как они названы в русской Victoria 3, а не своим переводом. Свои термины
  инструментов (index, lint, outline…) — в том же глоссарии, отдельным разделом.
- **Переезд документов:** русские правила при переносе переводятся на английский, русский текст становится первой
  версией `docs/ru/`.
- Проекты (`vic3_mods`, форк) живут по своим правилам: русские документы и коммиты, как сейчас.

## Песочница прогонов

Цель (пользователь 15.10): прогоны игры агентом не занимают экран, мышь и клавиатуру; песочница может брать всю
мощность ПК. Решение — ВМ Hyper-V на том же ПК.

- **Железо:** Ryzen 7 7800X3D (8 ядер / 16 потоков), 64 ГБ, RTX 5070 + встроенная Radeon, 788 ГБ свободно на `C:`.
- **Процессор и память:** ВМ получает все 16 потоков и до ~40 ГБ (динамическая память); хост и ВМ делят их — когда
  пользователь нагружает ПК, прогон медленнее, и наоборот. Скорость Vic3 упирается в процессор; потери Hyper-V —
  порядка 5–10 % (замерить `ld_speed.py`: игровой месяц на ПК и в ВМ).
- **Видеокарта:** GPU-P (`Add-VMGpuPartitionAdapter`) — доля RTX 5070, драйвер копируется с хоста. На клиентской
  Windows это неофициально (так делает Easy-GPU-PV); на RTX 50 — проверить. Запасной вариант — доля встроенной Radeon
  (слабая, но для прогона «ИИ за всех» на низких настройках может хватить). Проброс карты целиком (DDA) — только
  Windows Server.
- **Экран ВМ:** игре нужен дисплей — виртуальный монитор внутри ВМ; смотреть человеку — Parsec или консоль Hyper-V.
- **Steam:** один аккаунт в двух местах одновременно не играет. Проверить запуск Vic3 в ВМ при Steam в автономном
  режиме — тогда пользователь может играть на хосте во время прогона.
- **Устройство:** мост (`vic3-pc` → мост v2) работает **внутри ВМ**: запуск игры, логи, сейвы, скриншоты окна; агент на
  хосте говорит с ним по внутренней сети Hyper-V. Мод в ВМ — синхронизация с хоста (общая папка или `sync_mod`
  моста). Мастерская подтягивается сама по подпискам аккаунта.
- **После каждого обновления драйвера NVIDIA на хосте** — повторно скопировать драйвер в ВМ (скрипт).

Шаги. Пользователь (права администратора, один раз): проверка `Get-VMHostPartitionableGpu`, включение Hyper-V и
перезагрузка, образ Windows 11, установка Windows в ВМ, вход в Steam и установка игры в ВМ. Агент: скрипты создания
ВМ и копирования драйвера, мост в ВМ, навык `vic3-sandbox` — прогон в ВМ, замер скорости.

Порядок: после этапа 0 (не мешает остальным этапам), до этапа 6.
