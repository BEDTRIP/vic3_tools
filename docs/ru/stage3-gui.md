# Этап 3 — GUI: передача

Строка плана ([`plan.md`](plan.md), этап 3): `v3 gui resolve` (виджет с подставленными `using` / `blockoverride`),
справочник ванильных типов, шаблонов и текстур с образцами, `v3 gui set <файл> <путь> prop=…` и проверка, влезает ли
текст в ширину на всех 11 языках. Только ПК (файлы игры читаются на месте).

Написано 15.10.2026 в начале этапа, для сессии, которая его делает. Когда этап готов — удалить файл (или перенести
то, что ещё верно, в `usage.md`).

## Что уже есть

- **`vic3tools/gui/tree.py`** (с тестами, `tests/test_gui_tree.py`) — парсер `.gui`: `GNode(head, op, value,
  children, line, end_line, start, end, open, file)`. Понимает `type x = base { }`, `template x { }`,
  `block "x" { }`, `blockoverride "x" { }`, `types X { }`, типизированные значения (`color = hsv { }`), списки
  (`size = { 100% 40 }` → `is_list`, `scalar()` даёт `{ 100% 40 }`), голые слова. Помощники: `parse_file` (кеш по
  mtime), `walk`, `node_at(nodes, line)` (цепочка блоков вокруг строки), `find_def(nodes, "type"|"template", name)`,
  `GNode.props(key)`, `GNode.label()` (`name`, иначе `text` / `raw_text` / `datacontext`). `core/script.parse` для
  `.gui` **не годится**: не понимает `type a = b {` и `template a {`.
- **Индекс** (`vic3tools/index/db.py`) уже хранит определения `gui_type` и `gui_template` с диапазонами строк по
  всем модам набора: `SetIndex.defs(name)` в `index/query.py`. Где тип или шаблон используется (экземпляры,
  `using = …`) — `SetIndex.refs(name)`.
- **Кто побеждает** — `compat/winner.gui_type`: первая регистрация, файлы по имени по всем модам, порядок модов не
  важен, при равных именах — файл ближе к корню `gui/`. Для шаблонов брать тот же порядок (см. открытые вопросы).
- `v3 outline` (`index/query.outline`) — общее дерево любого файла скрипта; для работы с GUI лучше `gui/tree.py`.
- Плагин (`claude-plugin/`): навык `vic3-search` и хук. Новые команды GUI — добавить в таблицу навыка.

## Что выяснено о движке (1.13.11)

- `type ИМЯ = ОСНОВА { тело }` внутри `types ГРУППА { }`; ОСНОВА — встроенный виджет (`window`, `widget`,
  `flowcontainer`, `textbox`, `icon`, `button`, `hbox`/`vbox`…) или другой тип. Экземпляр — `ИМЯ = { … }` где угодно.
- `template ИМЯ { свойства }`; `using = ИМЯ` вставляет свойства шаблона на место (шаблоны используют шаблоны).
- `block "x" { по умолчанию }` в теле типа — «дырка»; экземпляр (или производный тип) заполняет её
  `blockoverride "x" { … }`. Дырки бывают на любой глубине тела: у `default_header` (`gui/shared/backgrounds.gui`
  233–270) `block "text"`, `"text_mod"`, `"margin"`, `"text_size"`, `"align"` лежат внутри
  `block "textbox"` › `flowcontainer` › `textbox`.
- Форматы текста (`default_format = "#title"`) — `gui/textformatting.gui` (55 `format = { name … format … }`);
  `title` — `"grey;shadow"`: цвет и тень, **ни размера, ни шрифта**.
- Шрифты: `game/fonts/fonts.font` — `fontfiles = { name group = { languages = {…} files = {…} } }` (группы по
  языкам; в первом файле глифы, остальные — запасные) и псевдонимы `font = { name fontstyle = { style fontfiles } }`:
  `standard_font` → `Game-OpenSans-Regular`; `OpenSans` (обычный, жирный, курсив); `EBGaramond`; `PlayfairDisplay`;
  `Fancy` → `ParadoxVictorian`. Файлы шрифтов — в `game/fonts/` и `clausewitz/fonts/` (`Open_Sans`, `NotoSans`,
  `Roboto_Mono`, там же `cw_fonts.font`). В ванильных `.gui`: `font = "standard_font"` 47 раз, `StandardGameFont` 7,
  `tools_font` 4. Шаблоны в `gui/shared/defaults.gui`: `regular_font` (EBGaramond 17), `tooltip_font` (OpenSans 15),
  `fontsize_large` 20, `fontsize_xl` 22, `fontsize_medium` 14 + шрифт подсказки….
- `elide_fontsize_min` (`gui/shared/buttons.gui` 892) = `elide = right` + `fontsize_min = 14`: длинный текст
  уменьшается до 14, потом обрезается «…».
- Константы `@имя = значение` задаются в начале `.gui` (в пределах файла; `@panel_width_plus_14` определена в
  нескольких файлах).

## Устройство

### `v3 gui resolve ФАЙЛ:СТРОКА` (также `--type ИМЯ`, `--prop КЛЮЧ[,КЛЮЧ]`, `--depth N`)

Взять экземпляр виджета вокруг СТРОКИ (`node_at`, самый внутренний блок, который не свойство), раскрыть, напечатать
с происхождением каждого свойства.

Раскрытие экземпляра `K = { тело }`:

1. Если K — GUI-тип (победитель по правилу выше), построить цепочку K → его основа → … до встроенного виджета: тела
   `[тело самой внутренней основы, …, тело K, тело экземпляра]`.
2. Переопределения: обходить тела от внешнего; `blockoverride "x"` берётся, если "x" ещё не занят; переданные сверху
   берутся первыми (допущение: побеждает самое внешнее, см. открытые вопросы).
3. Дети, тела от внутреннего: `blockoverride` — выбросить (использован); `block "x"` — дети переопределения, если
   оно есть, иначе свои; `using = T` — свойства T на место (рекурсивно); свойство — оставить; дочерний виджет —
   раскрыть так же, передав переопределения вниз.
4. У каждой строки вывода — происхождение: `файл:строка` свойства и путь, как оно попало
   (`via using fontsize_large ← block "text_size" of type default_header`). Ключ, повторённый позже, перекрывает
   прежний — отметить проигравший.

Ожидаемое для T5 замера (`gui/ld_cb_rate_panel.gui:31`, `--prop fontsize,fontsize_min,elide`):

```
default_header › block "textbox" › flowcontainer › textbox
  fontsize = 20      # vanilla gui/shared/defaults.gui:15  via using fontsize_large ← block "text_size" (backgrounds.gui:258)
  fontsize_min = 14  # vanilla gui/shared/buttons.gui:894  via using elide_fontsize_min (backgrounds.gui:244)
  elide = right      # vanilla gui/shared/buttons.gui:893  via using elide_fontsize_min (backgrounds.gui:244)
```

### Справочник: `v3 gui types ЗАПРОС`, `v3 gui templates ЗАПРОС`, `v3 gui textures ЗАПРОС`

- типы / шаблоны, в имени которых есть ЗАПРОС: определение `мод: файл:строка-конец`, основа (у типов), какие блоки
  тип предлагает (имена `block "…"` — что экземпляр может переопределить), сколько мест его используют (refs) и один
  пример экземпляра `файл:строка`;
- текстуры: файлы `.dds` (и `.png`) в `gfx/` набора, в пути которых есть ЗАПРОС, с шириной × высотой из заголовка DDS
  (байты 12–19: высота, ширина, little-endian) и модом, чей файл побеждает по пути.

### `v3 gui set ФАЙЛ:СТРОКА КЛЮЧ=ЗНАЧЕНИЕ [КЛЮЧ=ЗНАЧЕНИЕ…] [--find ТЕКСТ] [--dry]`

Виджет вокруг СТРОКИ (или единственный узел, у которого ключ или подпись содержит ТЕКСТ): заменить `КЛЮЧ = …` на его
собственном уровне (не во вложенных блоках) или вставить перед закрывающей `}` с отступом блока. Запись побайтовая
(`core/script.read` / `write` сохраняют BOM и концы строк). Вывести `файл:строка  было → стало`. Для T2: textbox на
`ld_cb_rate_panel.gui:467` и flowcontainer на 463 — `minimumsize="{ 130 40 }"` и т. д.

### `v3 gui fit ФАЙЛ:СТРОКА`

Для textbox: раскрыть (`font`, `fontsize`, `fontsize_min`, `elide`, `multiline`, `size` / `minimumsize` /
`maximumsize`, `margin`), взять ключ `text`, прочитать текст на всех 11 языках (определения ключей всех языков есть в
индексе; `loc_text` хранит только en/ru — остальное читать строкой из файла), измерить и сказать по каждому языку:
влезает / уменьшается до N пикселей / обрезается / переносится на N строк.

- Мерить без новых зависимостей: маленький читатель sfnt (`cmap` форматов 4 и 12, `hmtx`, `head.unitsPerEm`) —
  ширина = Σ advance × fontsize / unitsPerEm; глифа нет в первом файле — брать из следующего файла группы языка в
  `fonts.font`. Кернинг не учитывается (сказать об этом в выводе).
- Подстановки `[…]` и `$…$` — образец фиксированной длины (скажем, 8 символов "0"), форматирование `#x … #!` и
  значки `@x!` убрать (это делает `index/query._plain`).
- Ширина в `%` зависит от родителя — писать «относительно родителя», если цепочка родителей не даёт числа.

## Открытые вопросы — проверить, не угадывать

- Перекрывают ли внешние `blockoverride` внутренние и доходят ли до блоков во вложенных экземплярах типов?
  (Допущение: да; проверить на случае в ванили, где есть оба, или в игре.)
- Шаблон определён дважды: побеждает первый или последний? (Допущение — как у типов; `gui.log` может называть
  дубли.)
- Шрифт textbox без `font` — `standard_font`? (Проверить на простом ванильном textbox в игре.)
- Константы `@`: чьё значение действует, когда тип из файла A используется в файле B?
- Как проверять прогоном — дело песочницы (навык `vic3-sandbox` в `vic3_mods`, ВМ Hyper-V); снимок окна финансового
  центра отвечает на вопросы о шрифте и обрезке сразу.

## Готово, когда

- T5 отвечается одним вызовом `v3 gui resolve … --prop …`; правка T2 делается `v3 gui set` с точными строками (и
  `--dry` её показывает); `v3 gui fit` на подписи T2 показывает перенос при 100 и его отсутствие при 130.
- Тесты на маленьких примерах (`tests/`), `ruff`, `pytest`, `v3 docs check-ru` зелёные; `docs/usage.md` и
  `docs/ru/usage.md` описывают команды (обновить хеш в первой строке русского файла); в строке этапа 3 плана — «сделано»
  с коммитом; навык `vic3-search` перечисляет новые команды.

## Практические заметки по репо

- Код, имена, комментарии, `--help`, документы и коммиты — по-английски; вывод команд — через `vic3tools/i18n`
  (en + ru); длина строки 120; совместимость с Python 3.11 (CI гоняет 3.11 — без обратной косой и повторных кавычек
  внутри f-строк).
- Python писать инструментами Write / Edit, а не heredoc'ами `python - <<'EOF'` с `"\n"` или экранированием в
  регулярках: оболочка их съедает (уже несколько сломанных файлов так).
- Коммиты прямо в `main` с явными путями, push после каждого коммита (правила git — `vic3_mods/CLAUDE.md`).
- `vic3_mods` и форк используют пакет (`ld_pdx.py`, `vic3lib.py` — обёртки над `core/script.py`): правка
  `core/script.py` — только с `--check` всех их генераторов до и после (см. этап 1 в плане).
