# Как пользоваться `v3`

`v3` — одна команда для всех инструментов. У каждой подкоманды есть `--help`; вывод по умолчанию короткий, `--json`
выдаёт те же данные для других программ. `--lang en|ru` — язык вывода (по умолчанию — `lang` из конфига, затем язык
системы).

## Откуда читаются файлы

Ничего из игры в репо не хранится и никуда не копируется: инструменты читают три корня на месте.

| корень | что там | как находится |
| --- | --- | --- |
| `game` | установка игры: `game/` (скрипт, GUI, локализация, текстуры), `launcher/`, `binaries/` | Steam: библиотека из `libraryfolders.vdf`, в которой есть Victoria 3 |
| `workshop` | `steamapps/workshop/content/529340/<id>/` — моды мастерской как есть | та же библиотека Steam |
| `documents` | `Documents/Paradox Interactive/Victoria 3`: логи, сейвы, локальные моды, плейсеты лаунчера | папка «Документы» Windows (куда бы её ни перенесли, в том числе в OneDrive) |

Корни находятся сами. Поправить найденное — в файле конфига:

```toml
# vic3tools.toml
lang = "ru"

[roots]
game = 'D:\SteamLibrary\steamapps\common\Victoria 3'
```

Читаются два файла конфига, более поздний побеждает: пользовательский в домашней папке инструментов
(`%LOCALAPPDATA%\vic3tools\vic3tools.toml`, его пишет `v3 setup`), затем ближайший `vic3tools.toml` от текущей папки
вверх (свой у проекта). `V3_HOME` переносит домашнюю папку инструментов в другое место.

Там же кеш (`cache/`) и установленные программы (`bin/`, например tiger).

## Команды

| команда | что делает |
| --- | --- |
| `v3 where` | действующие корни и откуда взят каждый, версия игры, файлы конфига, кеш |
| `v3 setup` | один раз на машину: найти корни, записать пользовательский конфиг, построить кеш (пока — глоссарий), проверить tiger |
| `v3 doctor` | что готово, а что нет; код выхода 1, если чего-то не хватает |
| `v3 glossary <текст>` | как термин называет сама игра — по-английски и по-русски (`--all-langs` — все одиннадцать языков), из локализации игры; плюс термины самих инструментов |
| `v3 docs check-ru` | в этом репо: актуальны ли русские переводы в `docs/ru/` |
| `v3 hook pre-tool-use` | хук Claude Code из плагина (`claude-plugin/`): grep по имени или чтение большого файла целиком в папках игры и модов получают вместо этого ответ индекса, один раз за сессию |
| `v3 hook post-tool-use` | хук плагина после правки: изменённый `.gui` / `.txt` / `.yml` мода плейсета проходит быстрые правила `v3 lint` (скобки, BOM, правила проекта, GUI-типы, которые не применяются, ширина текста у изменённых строк); новые отчёты уходят агенту как контекст |
| `v3 lint [МОД]` | проверка мода (по умолчанию — последнего в наборе): vic3-tiger с модами перед ним как зависимостями плюс наши правила; известные отчёты не показаны (база известных, подавления); по файлу и строке. `--file Ф` — один файл, `--no-tiger` — только наши правила (около секунды), `--key`, `--severity`, `--all`, `--baseline` — принять все текущие отчёты как известные |
| `v3 def <имя>…` | где имя определено — записи (с диапазоном строк), GUI-типы и шаблоны, ключи локализации — и чьё определение побеждает |
| `v3 refs <имя>` | где имя используется: `файл:строка`, в какой записи, под какими ключами (`set_variable>name`), пишет ли; файлы, которые игра не читает (`_archive/`, перекрытые по пути), — отдельно; шаблон (`prefix_*`) — сводка по всем подходящим именам |
| `v3 loc <КЛЮЧ>` | текст ключа локализации по-английски и по-русски, все определения и какое видно; `v3 loc --text "…"` — ключ по тексту, как его видит игрок (подстановки заполнены) |
| `v3 outline <файл>` | дерево записей / GUI-виджетов файла с диапазонами строк и именами (`name` виджета, иначе его `text`); `--find X` — узлы, у которых ключ или имя содержит X, с путём к ним; `--at СТРОКА` — узлы вокруг строки. Читать до того, как открывать большой файл |
| `v3 gui resolve ФАЙЛ:СТРОКА` | виджет у строки так, как его строит игра — цепочка типов, шаблоны `using`, подставленные `block` / `blockoverride`, — каждое свойство с `файл:строка` и путём, которым оно пришло; `--prop fontsize,elide` — только они, с виджетами над ними; `--type ИМЯ` — тип по имени |
| `v3 gui types Q`, `v3 gui templates Q` | справочник: типы / шаблоны, в имени которых есть Q, — определение, база, блоки, которые тип даёт перекрыть, число использований, один пример (сначала из ванили) |
| `v3 gui textures Q` | файлы `.dds` / `.png` под `gfx/`, в пути которых есть Q, с шириной × высотой и модом, чья копия загружается |
| `v3 gui set ФАЙЛ:СТРОКА КЛЮЧ=ЗНАЧЕНИЕ…` | задать свойства виджета у строки: заменить на его уровне или вставить перед его `}`; `--find ТЕКСТ` выбирает виджет по ключу или имени, `--dry` только показывает правку |
| `v3 gui fit ФАЙЛ:СТРОКА` | влезает ли текст текстбокса в ширину на всех 11 языках: влезает, переносится на N строк, уменьшается до fontsize N, обрезается; `--width N` — а если ширина N |
| `v3 playsets` | плейсеты лаунчера, активный отмечен |
| `v3 mods` | моды набора в порядке загрузки |
| `v3 winner <папка> <ключ>…` | все определения записи в порядке загрузки, что делает каждое (создаёт, заменяет, вливается, игнорируется, теряется) и какое берёт игра; `v3 winner loc <ключ> --lang russian`, `v3 winner gui <тип>` — то же для ключа локализации и GUI-типа |
| `v3 conflicts <A> <B>` | что определяют оба мода (или обе группы, `--groups`): ключи записей по папкам, пути файлов, ключи локализации, GUI-типы, id событий — с `файл:строка` с обеих сторон |
| `v3 matrix` | то же числами для каждой пары модов набора (или групп, `--groups`) |
| `v3 audit replace <мод>` | тела `REPLACE:` мода без полей заменяемой записи (все они теряются); `--declared` — намеренные пропуски |
| `v3 audit stale <мод>` | полные тела мода без полей, которые есть у ванили, — обычно копия из прошлой версии игры |
| `v3 audit loc-dead <мод>` | ключи локализации мода, которые никогда не покажутся: определены раньше под другим путём (перенести в `replace/`) |

### Набор модов и кто побеждает

Команды про моды работают на наборе: сначала ваниль, затем моды в порядке загрузки. По умолчанию — активный плейсет
лаунчера (только чтение `launcher-v2.sqlite`); `--playset ИМЯ` — другой, `--mods ПАПКА…` — папки списком, `--set
ФАЙЛ` — файл набора:

```json
{"load_order": ["../mods_out/.vanilla", "../mods_out/CMF", "my_mod"], "labels": {"my_mod": "Mine"}}
```

Пути — относительно файла; первой может стоять копия ванили (в ней есть `checksum_manifest.txt`), иначе впереди
ставится установленная игра. `[mod_paths]` в `vic3tools.toml` подменяет папку мода плейсета по имени (например, ваша
git-копия вместо копии в `mod/`). Для `matrix` и `conflicts` `--groups ФАЙЛ` задаёт группы модов:
`{"blocks": {"Группа": ["mod1", "mod2"]}, "order": ["Группа", …]}`.

Правила, по которым считает `v3 winner` (наблюдения в игре, 1.13):

- **главный — порядок модов; имя файла решает только внутри мода** (побайтово: `_` раньше букв, заглавные раньше
  строчных, `~` последней);
- файл с **тем же относительным путём** заменяет файл более раннего мода целиком;
- **записи**: более позднее голое определение заменяет запись и все `INJECT:` до него; `REPLACE:` заменяет её целиком;
  `INJECT:` вливается в неё; варианты `TRY_` пропускают отсутствующую запись, `_OR_CREATE` — создают её. В
  `scripted_effects`, `scripted_triggers` и `script_values` голый повтор **не** переопределяет — остаётся первое;
- **локализация**: побеждает первое определение ключа; определение в папке `replace/` перекрывает остальные;
- **GUI-типы**: побеждает первая регистрация, файлы — по имени файла по всем модам сразу (порядок модов не важен), при
  равных именах раньше файл ближе к корню `gui/`. Проигравший тип `gui.log` называет «already registered».

Каждый мод индексируется в кеш один раз (`cache/index/`); дальше перечитываются только изменённые файлы (ваниль с
нуля ~7 с, потом ~2 с).

### Индекс

`v3 def`, `refs`, `loc` и команды совместимости читают по одной базе SQLite на мод в кеше (`cache/index/`); её строит
`v3 setup` для активного плейсета или первый вызов, и каждый вызов обновляет по изменённым файлам (ваниль: ~40 с один
раз, дальше ~1 с). В ней:

- **определения** — верхние записи `.txt`, GUI-`type` и `template`, ключи локализации всех языков;
- **ссылки** — каждый идентификатор вне комментариев в файлах скрипта и GUI (и внутри строк, так что
  `[GetVariable('x')]` считается) и части `[…]` / `$…$` английской локализации, у каждой — запись, в которой она
  стоит, и ключи над ней. Простые слова в нижнем регистре без `_` (`yes`, `limit`, `wood`) не хранятся; для них `v3
  refs` читает файлы;
- **тексты локализации** по-английски и по-русски.

Загружаемыми считаются только папки, которые читает игра (`common/`, `events/`, `gui/`, `localization/`, `map_data/`,
`gfx/`…); остальное в папке мода (документы, `_archive/`) индексируется, но помечено «не загружается».

### GUI

`v3 gui` читает `.gui` своим разборщиком (`type x = base {`, `template`, `block` / `blockoverride`, типизированные
значения вроде `color = hsv { … }`), типы и шаблоны находит через индекс. ФАЙЛ — путь или путь внутри набора
(`gui/my_panel.gui:120` — та копия, что загружается).

```
> v3 gui resolve gui/ld_cb_rate_panel.gui:31 --prop fontsize,fontsize_min
default_header  [default_header_properties › widget]  E&F: Ledgerdemain: gui/ld_cb_rate_panel.gui:31
default_header › flowcontainer › textbox
  fontsize = 17  # vanilla: gui/shared/defaults.gui:4  via using regular_font (defaults.gui:116) ← type textbox …  (перекрыто в defaults.gui:15)
  fontsize_min = 14  # vanilla: gui/shared/buttons.gui:894  via using elide_fontsize_min (backgrounds.gui:244) ← …
  fontsize = 20  # vanilla: gui/shared/defaults.gui:15  via using fontsize_large (backgrounds.gui:259) ← block "text_size" (backgrounds.gui:258) ← …
```

Как раскрывается виджет:

- экземпляр `K = { … }` типа `K`: тела цепочки `K → база → …` до встроенного виджета, начиная с самой внутренней базы,
  затем собственное тело экземпляра; свойство, повторённое позже, побеждает (проигравшее помечено «перекрыто в»);
  действия (`onclick`, `state`…) могут повторяться;
- `blockoverride "x"`: побеждает самый внешний — переданный от объемлющего виджета, затем экземпляра, затем цепочки
  типа снаружи внутрь — и он доходит и до `block "x"` вложенных виджетов;
- `using = T` вставляет свойства шаблона (шаблоны используют шаблоны);
- тип или шаблон определён несколько раз: берётся первый, файлы упорядочены по имени файла через все моды (как
  `v3 winner gui`);
- константы `@имя` показаны со значением, если их определяет тот же файл.

`v3 gui fit` меряет шрифтами самой игры: `fonts/*.font` игры, движка (`clausewitz/fonts`) и модов дают файлы
семейства по языкам (в первом — глифы, остальные — запасные); ширина — сумма продвижений глифов (кернинг не учтён).
Текст — ключ локализации из `text` на каждом языке, как его видит игрок (`$KEY$` и `[concept_x]` заменены их текстом;
прочие `[…]` считаются как `00000000`; форматирование и иконки выброшены), или `raw_text`. Место — `max_width`, иначе
`maximumsize`, иначе фиксированный `size`, минус `margin`; ширина в `%` — доля родителя, не меряется. Если указать
на виджет, внутри которого текстбокс (заголовок), меряется первый текст внутри.

В игре пока не проверено (допущения выше): какой `blockoverride` побеждает, когда есть и внешний, и внутренний; что
шаблоны следуют правилу типов; шрифт текстбокса без шрифта (ванильный `type textbox` даёт `regular_font`, EBGaramond 17;
совсем без шрифта принят `standard_font`); шаг уменьшения при `fontsize_min` (принят целый пиксель); `@константа`,
определённая не в том файле, где используется.

### Проверки: `v3 lint`

`v3 lint` запускает [vic3-tiger](https://github.com/amtep/tiger) (ставится в `bin/` инструментов) на мод со
сгенерированным конфигом: собственный `vic3-tiger.conf` мода плюс `load_mod` для каждого мода перед ним в наборе, чтобы
определённое в CMF или другой зависимости не было «missing». JSON tiger кэшируется и перезапускается, только когда
меняется файл этих модов (форк с CMF и ETF: ~4 с, затем ~0.1 с). Остаются только отчёты, указывающие в сам мод.

Наши правила поверх (`--rules` выбирает):

| правило | что находит |
| --- | --- |
| `gui-type-ignored` | GUI-тип мода, который никогда не применяется: его раньше регистрирует другой файл (файлы по имени через все моды) |
| `replace-fields` | тело `REPLACE:` без полей заменяемой записи — они теряются |
| `loc-dead` | ключ локализации, определённый раньше под другим путём: никогда не покажется (перенести в `replace/`) |
| `text-fit` | однострочный текстбокс со своей шириной, текст которого обрезается или вылезает на языке из `--langs` |
| `braces` | `{` и `}` не сходятся в файле скрипта / GUI (строка, где ломается) |
| `bom` | файл локализации без BOM (не читается), `.txt` с не-ASCII текстом без BOM (читается неверно); для `.gui` — предупреждение |
| `rule:<имя>` | правила проекта: `[[rule]]` в `v3-lint.toml` мода — `name`, `files` (глобы), `pattern` (регулярное выражение), `message`, `severity` |

Известные отчёты лежат в корне мода, чтобы их видели все сессии и машины:

- `v3-lint-baseline.json` — пишет `v3 lint --baseline`: все текущие отчёты приняты как известные. Отчёт узнаётся по
  источнику, ключу, файлу, сообщению и тексту своей строки (не по номеру строки), со счётчиком — правки в другом месте
  его не возвращают, новый такой же покажется;
- `[[suppress]]` в `v3-lint.toml` — руками, с причиной: `key` и `file` (глобы), `message` и `text` (подстроки), `why`.

```toml
# v3-lint.toml
[[suppress]]
key = "missing-item"
file = "common/scripted_effects/ld_listing_switch.txt"
why = "здания других модов, проверяются has_building_type во время игры"

[[rule]]
name = "no-debug-log"
files = ["common/**", "events/**"]
pattern = "debug_log"
message = "оставлен отладочный вывод"
```

Хук плагина после правки запускает правила, которым нужен только этот файл (не tiger), и сообщает агенту о новых
отчётах в том же ходе.

### Глоссарий

Строится командой `v3 setup` для установленной версии игры (`cache/glossary-<версия>.sqlite`): каждый ключ
локализации, у которого английский текст — короткое простое название (без `[...]`, `$...$`, переносов строк; не
больше шести слов), с его текстом на каждом языке. Поиск — по ключу или тексту на любом языке, без учёта регистра;
понятия игры (`concept_*`) — первыми. Нужен, чтобы называть вещи так, как их называет игра, а не своим переводом:

```
> v3 glossary институт --limit 2
concept_institution — en: Institution | ru: Институт
LAW_TYPE_TYPE_DESC_INSTITUTION — en: Institution | ru: Институт
```

## Переводы документов

Оригинал — английский; `docs/ru/` — зеркало документов для людей. Каждый перевод начинается с отметки, с какой версии
английского он сделан:

```
<!-- source: docs/usage.md @ 1a2b3c4d5e6f -->
```

Хеш — git-хеш blob английского файла (`git hash-object docs/usage.md`). `v3 docs check-ru` показывает перевод, чей
источник с тех пор изменился, и документы без перевода (это заметка, не ошибка). Обновив перевод — поставьте новый
хеш в первую строку.
